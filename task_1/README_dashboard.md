# Дашборд Taipy «SOC · триаж алертов SIEM»

Интерактивный дашборд по карточкам инцидентов `iavd_incidents_raw`: поток алертов, исходы карточек, скорость реакции, распределения и потоки «категория → вердикт». На листах — только KPI-плитки и графики. Выводы с цифрами вынесены в отчёт [`REPORT.md`](REPORT.md), его собирает `report.py` из тех же расчётов, что и плитки. Модели здесь нет: качество советника — отдельное задание.

## Файлы

| Файл | Что внутри |
|---|---|
| `dashboard.py` | приложение Taipy: страницы, фильтры, обработчики |
| `dashboard_data.py` | загрузка parquet, фильтры (период, тип дня, источник, критичность), форматирование чисел по-русски |
| `dashboard_kpis.py` | KPI-плитки каждой страницы: число, короткий контекст, отметка «обратить внимание» |
| `dashboard_charts.py` | функции «данные → Plotly-фигура», единый стиль и палитра |
| `dashboard_insights.py` | аналитические выводы для отчёта |
| `report.py` | собирает `REPORT.md` |
| `REPORT.md` | отчёт к дашборду за весь период |
| `dashboard.css` | оформление страниц |
| `test_logic.py` | синтетические проверки без parquet и без запуска Taipy |

Файлы лежат в `task_1` рядом с `etl.py` и `train.py`. Пути к данным считаются от этой папки, поэтому команды ниже запускаются из неё.

## Данные

```
data/agg/features.parquet      # результат etl.py
data/agg/agg_top_src.parquet   # результат etl.py
data/dataframe.parquet         # таблица периодов 7 / 30 / 90 / 180 дней
data/calendar.parquet          # календарь с типом дня
```

## Запуск

Нужен Python 3.12: свежий Taipy на PyPI не собран под 3.13 и 3.14.

```bash
cd task_1
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python "taipy>=4.1" plotly "pandas<3" numpy scipy pyarrow
.venv/bin/python etl.py --full
.venv/bin/python dashboard.py
```

Откройте http://localhost:5002. Если `data/agg/features.parquet` ещё нет, дашборд не запустится: сначала `etl.py --full`. Без `--full` `etl.py` берёт учебную выборку из 1 000 карточек — дашборд работает и на ней, окна периодов сдвигаются к последней дате выборки.

Пересобрать отчёт после обновления данных: `.venv/bin/python report.py`.

Проверки логики без данных: `.venv/bin/python -m unittest test_logic.py`.

## Страницы

| Страница | KPI-плитки | Графики |
|---|---|---|
| Обзор | объём потока, доля FP, инциденты, ложных на инцидент, без вердикта, скорость реакции, реакция на критические, тренд | поток по дням, исходы во времени, состав вердиктов |
| Сравнение | доля топ-10 правил, правила-«шумы», самая «шумная» категория IRP, пик нагрузки | топ правил SIEM, отклонение доли FP, нагрузка «день × час», таблица топ-15 правил |
| Распределения | ждут дольше суток, «мгновенные» взятия, часы выше «среднее + 3σ», L2 против L1 | время взятия в работу, QQ-график, признаки инцидентов и FP, группы, L1 / L2 / ГИБ |
| Потоки и плотность | изменение потока, главный вклад, правила без инцидентов, внешние адреса | категория → вердикт, waterfall, hexbin, топ адресов-источников, bubble chart |

Плитка с красной полосой, розовой заливкой и значком ▲ — сигнал, на который стоит обратить внимание. Пороги — в `dashboard_kpis.py`.

## Оговорки по данным

- **Время хранится в миллисекундах** — проверено по разнице дат «Создан» и «Дата взятия в работу».
- **≈31 % карточек берутся в работу «мгновенно»** (< 0,6 с, автоматика). На логарифмической шкале ноль не показать, поэтому медианы времени считаются без них, а их доля вынесена в отдельную плитку.
- **≈23 % карточек без вердикта.** Там, где их много, доли FP и реальных инцидентов занижены.
- **Доля False Positive — решение аналитика по карточке**, а не доля трудозатрат SOC.
- **Топ адресов-источников** — агрегат `etl.py` за весь период, фильтры к нему не применяются.
