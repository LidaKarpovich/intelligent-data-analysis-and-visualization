# Дашборд Taipy «SOC · триаж алертов SIEM» (без ML)

Интерактивный дашборд по карточкам инцидентов `iavd_incidents_raw`: поток алертов, исходы, распределения времени реакции, потоки «категория → вердикт». Выбор каждой диаграммы сделан по «Рекомендациям по выбору диаграмм v1.0», оформление — по «Чек-листу очистки графика» (занятие 2.2). ROC/PR, SHAP, PDP и Bias–Variance (раздел 5 методички) сюда намеренно не входят.

## Файлы

| Файл | Что внутри |
|---|---|
| `dashboard.py` | приложение Taipy: страницы, фильтры, обработчики, тексты-выводы |
| `dashboard_data.py` | загрузка parquet, фильтры (период, тип дня, источник, критичность), форматирование чисел по-русски |
| `dashboard_charts.py` | функции «данные → Plotly-фигура», единый стиль и палитра |
| `dashboard.css` | оформление страниц |


## Данные

Используются только файлы, которые уже есть в проекте:

```
data/agg/features.parquet      # результат etl.py
data/agg/agg_top_src.parquet   # результат etl.py
data/dataframe.parquet         # таблица периодов 7 / 30 / 90 / 180 дней
data/calendar.parquet          # календарь с типом дня
```

## Запуск

```bash
pip install "taipy>=4.0" plotly pandas numpy scipy pyarrow
python etl.py --full        # если features.parquet ещё не построен
python dashboard.py
```

Откройте http://localhost:5002 (порт 5002, чтобы не конфликтовать с ML-дашбордом `main.py` на 5001).

| Страница | Диаграммы |
|---|---|
| Обзор | KPI, линейный график по дням, 100-процентная столбчатая с накоплением, столбцы долей вердиктов |
| Сравнение | линейчатая (топ правил), дивергентная (отклонение доли FP от средней), тепловая карта «день × час», таблица |

Под каждым графиком — короткий вывод, пересчитываемый по фильтрам, и строка «зачем этот тип / когда не подходит».

## Важные решения

- **Время в миллисекундах.** «Период взятия в работу» и «Время решения» сверены с разницей дат «Создан» и «Дата взятия в работу»: это миллисекунды (как и считает `etl.py`).
- **≈28 % карточек берутся в работу «мгновенно»** (< 0,6 с, автоматика). На логарифмической шкале ноль не показать, поэтому они исключены из гистограмм и скрипок, а их доля подписана в выводе.
- **Доля False Positive — операционный вердикт аналитика**, а не FPR модели.
- **Bubble Chart.** В методичке Y — число сработавших правил, размер — критичность. В данных число правил в карточке почти всегда 1, а средняя критичность правил лежит в узком диапазоне 1,7–3,0 — по правилу «когда НЕ использовать» такой размер не считывается. Поэтому Y — доля «Решён», размер — число карточек, критичность — в подсказке.
- **Hexbin** нарисован настоящими шестиугольниками (алгоритм `matplotlib.hexbin`), а не прямоугольной 2D-гистограммой.
- **Dot Plot** строится по агрегату `agg_top_src.parquet` за весь период — фильтры к нему не применяются (это подписано на графике).
- Палитры проверены на различимость при дальтонизме: синий — False Positive, оранжевый — реальный инцидент, порядковая синяя шкала — критичность и линии L1/L2/ГИБ.
