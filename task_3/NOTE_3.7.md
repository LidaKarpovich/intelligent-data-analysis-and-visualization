# Практика 3.7 · Записка команды `team = 5` (ML-трек, Taipy)

**Модель:** `lgbm_gate1__v001` · **Рабочий порог:** `τ = 0,0193` · **Набор команды:** `team = 5` (8 карточек: 2 TP, 2 FP, 2 FN, 2 TN; данные учебные, условные).

## 1. Разбор карточки FN (`EntityId = 523480`, пропуск инцидента)

1. **Что видит модель:** В карточке `523480` (FN, факт — реальный инцидент (y = 1), правило `TTS_24_Security_Tool_Shutdown`) модель дала оценку `p = 0,000007` (0,0007 %) при пороге `0,0193`; решение — **FP (отложить)** (запас до порога −7,96 log-odds).
2. **Почему так:** Наибольший вклад дали «Текст алерта SIEM» = `Устройство microsoft windows Anti-virus было отк` (−1,193), «Частота правила в обучении» *(сконструирован)* = `0.006552` (−0,553), «Команда» = `security_product_state_off ; dr.web anti-virus` (+0,464); вклады в логарифме шансов, `base (-8,8524) + Σ (−3,0377) = -11,8901` сходится (`|σ(raw) − p| = 0.0e+00`).
3. **Что делать:** Чтобы исправить поведение модели, возможны: **данные** — включить в дообучение свежие кейсы отключения СЗИ (`TTS_24_Security_Tool_Shutdown`), где шаблонный текст алерта сейчас даёт −1,193 в сторону FP; **порог** — сдвиг порога не поможет (карточка ниже τ на −7,96 log-odds); **признак** — выделить явный признак отключения антивируса из поля `Команда` (`security_product_state_off`), перевесив шаблонный текст алерта. **Выбираю:** **данные (дообучение на свежих месяцах)**, потому что карточка провалена в слепое пятно модели (20 из 20 ближайших соседей по SHAP — TN).

## 2. Разбор карточки FP (`EntityId = 526930`, ложная тревога)

1. **Что видит модель:** В карточке `526930` (FP, факт — ложная тревога, FP (y = 0), правило `GL_OS_WIN_SYS_S01_Replay_Attack_Detected`) модель дала оценку `p = 0,031811` (3,18 %) при пороге `0,0193`; решение — **инцидент (в приоритет)** (запас до порога +0,51 log-odds).
2. **Почему так:** Наибольший вклад дали «Число значений инцидента» *(сконструирован)* = `0` (+1,141), «Команда» = `— (пропуск)` (+0,744), «Текст алерта SIEM» = `— (пропуск)` (+0,668); вклады в логарифме шансов, `base (-8,8524) + Σ (+5,4368) = -3,4156` сходится (`|σ(raw) − p| = 0.0e+00`).
3. **Что делать:** Чтобы исправить поведение модели, возможны: **данные** — восстановить заполнение полей обогащения (`Алерт`, `Вендор из сием`, `Команда`, `Возраст события`), пропуски которых сформировали 4 главных вклада в сторону инцидента; **порог** — поднятие τ до 0,0350 отсекает оба FP команды 5 (запас +0,43 и +0,51), но требует пересчёта матрицы ошибок на потоке из-за риска роста FN; **признак** — ограничить положительный вес пустых значений/нулей, чтобы сбой обогащения не повышал скор. **Выбираю:** **данные (вернуть обогащение)**, потому что модель сработала на отсутствие информации, а среди 20-NN этой карточки — 0 % реальных инцидентов.

*Примечание о втором кейсе:* на карточке TP **`521996`** (`p = 40,5 %`) объяснение, напротив, подтверждается данными (внешний IP `src_is_private = 0` +2,740, частота правила +1,180, алерт сканера `zgrab` +0,842; 9 из 12 признаков подтверждены 95 % ДИ Уилсона, 85 % среди 20-NN — инциденты).
